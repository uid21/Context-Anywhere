# 交给 Agent 部署 Context Anywhere

把下面整段交给能访问此仓库的 Agent。可以在末尾附上目标 Obsidian 库和要共享的路径。上传凭据、读取密码和 Cloudflare 令牌请留在密码管理器或对应的授权入口里。

```text
请帮我把当前仓库的 Context Anywhere 部署到我自己的 Cloudflare 账号，接通 Obsidian 的 AI Bridge 和 AI 客户端的远程 MCP。请直接执行你有权限的步骤，做到实际读到一篇允许同步的笔记。

1. 先读当前仓库的 AGENTS.md、README.zh-CN.md 和对应的部署文档。有 Windows 桌面时优先走 installer/README.md 的发布版向导。macOS、Linux 或只有终端时走 docs/manual-setup.zh-CN.md。按当前仓库和发行包核对命令、路径和版本。需要我登录、启用 R2、完成二次验证或在 OAuth 页输入密码时，把交互交给我，完成后继续余下步骤。
2. 写入前核对目标 Cloudflare 账号、Obsidian 库路径和共享范围。先根据该库的 AI Bridge 设置和 Cloudflare 资源判断是否已有镜像。已有镜像时走恢复或连接，保留绑定、密钥、OAuth 授权和插件设置。首次部署时用独立 Worker、R2 桶和 OAuth KV。账号或库无法唯一确定时，集中问我缺的那几项。共享范围没指定时，用测试库或经我确认的测试文件夹起步，保留明确的允许列表，附件和双向同步默认关闭。整库同步由我明确选择。
3. 按部署入口配置上传凭据和读取密码，分别使用独立的随机值。命令行部署保留 AI_MIRROR 和 OAUTH_KV 绑定名，按文档配置 MIRROR_TOKEN 和 MIRROR_READ_KEY。使用受保护的输入或存储传递凭据。聊天、日志、命令历史和提交里只记录非敏感结果。只处理这次指定的 AI 镜像与知识库，其中涉及私人库时沿用 AGENTS.md 的测试验收要求。
4. 在专用测试部署用无敏感信息且带唯一标记的笔记验证同步和 MCP，确认允许范围内的笔记可搜索、可读取，范围外的笔记不可见。按 AGENTS.md 清理测试数据和临时凭据。给目标 Obsidian 库配置或导入 AI Bridge 并同步，记录 Worker 根地址和以 /mcp 结尾的地址。在我的 AI 客户端添加远程 MCP，选 OAuth，在刚核对过的镜像授权页输入读取密码，读取一篇已获准共享的笔记。把真实客户端的验证结果和仅通过工具验证的结果分别记录。
5. 最后给我 Cloudflare 账号与资源名、Worker 地址、MCP 地址、目标库与同步范围、实际执行过的验证及结果。若还有一步需要我操作，说明在哪个界面、完成后如何接着验证。凭据和私有笔记正文留在原来的安全存储和应用中。
```
